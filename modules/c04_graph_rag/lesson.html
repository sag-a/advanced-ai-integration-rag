Graph RAG

Before class, Claude reads each passage once and records the entities and quoted relationships it states. At question time, vector search finds a few seed passages, the graph walks to passages that mention connected entities, and the merged ranking goes to the same answer step as Base RAG.

Building the index prepare · paid · once

  1. Read passages from Chroma

    The graph reuses the exact chunks already in the collection, in chunk order. It never writes to Chroma.

    graph_rag/__init__.py prepare() · store.read_documents

  2. Extract one passage at a time

    Claude (at temperature 0 on models that still accept one) gets the passage as numbered source lines plus the running entity catalog, and returns a ChunkExtraction: entities with canonical English ids and Greek and English aliases, and relationships with polarity and a first/last line range.

    graph_rag/index.py · schema.py · templates/extraction.j2

  3. Copy quotes, then validate

    The application copies the quote from the cited lines itself. It rejects duplicate entity ids, relationship endpoints that were not declared, and quotes that are not an exact substring of the passage.

    index.py validate_extraction()

  4. Retry with feedback

    If a check fails, the error goes back to Claude and it tries again, at most three times. A failed passage stops the build, and nothing is saved until every passage succeeds.

    index.py extract()

  5. Merge and save

    Entities are merged by normalized id and their aliases collected. The graph is saved with a contract of everything it depends on: the PDF, the chunking, the model and the prompt. If any of them changes, the graph is refused.

    index.py assemble() · load_index()

Query time GraphRetriever

  1. Vector seeds

    A normal Chroma query, capped at min(3, top_k) passages. These are the starting points.

    retrieval.py __call__ · stage “graph-vector-seeds”

  2. Pick start entities

    Entities extracted from the seed passages are the starting points. Those whose alias appears as a whole word in the question come first, then by seed rank. At most four.

    retrieval.py start_entities()

  3. Breadth-first walk

    Follow relationships touching the frontier for up to two hops, stopping at 30 facts. Each fact contributes the passage it was extracted from, up to 12 passages including the seeds.

    retrieval.py walk() · MAX_HOPS=2, MAX_FACTS=30, MAX_PASSAGES=12

  4. Rank

    The three seeds stay first. Chroma ranks the graph's passages by distance to the question, and they fill the remaining places up to top_k, closest first.

    retrieval.py rank()

  5. Fallback

    If the walk adds too few passages, the remaining places are filled with plain vector results, so Graph RAG always returns top_k passages like Base RAG.

    “Graph expansion contributed no additional passages”

Index contract what invalidates graph.json

The index stores a contract. On load, the current code recomputes it and refuses a mismatch with “Graph index is incompatible”. Any change below means building a new index at a new path.

Contract fieldChanges when
extraction_modelYou pass a different --model, even only to ask questions
prompt_idThe rendered extraction template changes
schema_idChunkExtraction fields or descriptions change
collection, corpus_id, sourcesA different collection or changed PDFs
embedding_contract_id, chunk_config_idEncoder or chunking changes
passagesAny chunk text or metadata changes

Loading also re-checks that every quote is still in its passage.

Run it

# the index ships with the repository; rebuild only for another model or corpus (about 30 calls)
./rag prepare --architecture graph_rag

# validate the index against the current code
./rag check --architecture graph_rag

# ask, with the traversal shown in the CLI and UI panels
./rag ask --process --architecture graph_rag "Πότε λήγουν οι Καρδιές;"   # shows seeds, traversal, selection

# a separate index for another model or collection
./rag prepare --architecture graph_rag --model claude-sonnet-4-5 \
  --option graph_index=outputs/graph_rag/sonnet/graph.json

Demo questions

Μπορώ να εξαργυρώσω τις Καρδιές για μετρητά; · Can I redeem Hearts for cash?

Anchors on hearts and walks the negative edges to cash, products and services. Good for showing that polarity survives extraction: the quote contains the “cannot”.

Who can join Magenta Moments and what do members get?

Uses both hops and hits the 30-relationship cap. Watch the hub entity magenta_moments: it pulls in edges about the company (ote) and liability, which spend the budget without helping. The answer still cites §2.1 (joining), §1 (what members get) and §3.4. Compare the passage list with Base RAG on the same question.

Πότε λήγουν οι Καρδιές; · When do Hearts expire?

A direct question. The expiry passage is already a seed, so watch whether expansion adds anything. If it adds nothing, the fallback message appears and the answer matches Base RAG.

Pitfalls before class

  • Any non-default --model breaks Graph RAG.The model is part of the index contract, so ./rag ask --architecture graph_rag --model … fails with “Graph index is incompatible”. Keep the default model or point graph_index at an index built with that model.
  • outputs/graph_rag/expanded-v1 belongs to another collection.Loading it with the default collection fails as designed. It is not a bug to fix live.
