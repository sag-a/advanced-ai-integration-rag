Agentic RAG

Retrieval becomes a small research job. A Deep Agents coordinator reads a topic skill, searches, reads exact clauses, checks what is still missing and finally selects passage IDs. It never writes the answer. The shared generator answers from the passages it picked, exactly as in Base RAG.

Who does what

The research loop typical order

  1. Read the matching skill

    The coordinator reads the SKILL.md that matches the topic. The guard refuses search_pdf and read_clause until at least one skill has been read and answers with an error naming the three skill files.

    guard.py wrap_tool_call · event “skill_required”

  2. Search

    search_pdf runs the same Chroma query as Base RAG and returns passages with chunk IDs, pages and clause labels, plus how many were new and how many searches remain.

    tools.py search_pdf

  3. Read exact clauses

    When a hit mentions a clause like 3.3, read_clause returns every chunk with that label, including fragments split across chunks.

    tools.py read_clause

  4. Assess coverage

    assess_evidence records a public checklist: covered topics, gaps and next action. It adds no evidence; it makes the agent's progress visible in the logs.

    tools.py assess_evidence

  5. Delegate, only for multi-topic questions

    The coordinator may hand one focused topic to the helper with task, one at a time, at most twice. The helper returns chunk IDs, not an answer.

    retrieval.py build_agent · helper subagent

  6. Select evidence

    select_evidence takes distinct, already retrieved chunk IDs, at most top_k. An empty list means the corpus cannot answer. If the agent stops without selecting, it gets one explicit reminder; a second miss fails the turn.

    tools.py select_evidence · retrieval.py “selection_required”

Skills guidance, not evidence

Three Markdown skills are loaded into the agent's virtual filesystem for each turn. They tell the agent how to research a topic. The prompt states that they are not facts, and only retrieved passages can be selected.

membership

Joining, registering, leaving, rejoining. Treats joining and registration as separate questions and never decides personal eligibility.

hearts

Earning, uses, transfers, restrictions, expiry. Checks negative wording and keeps the calendar rule verbatim.

coupons

Codes, reuse, redemption marking, validity. Separates getting, using, marking and expired codes.

Files: architectures/agentic_rag/skills/*/SKILL.md. Their hash is recorded as skills_id in every retrieval's details and eval report.

Exceeding a budget fails the turn

There is no partial answer. When a limit is hit the guard raises an error, the turn ends with “no answer was accepted”, and the user can retry. That is deliberate: an agent that ran out of budget has not shown its evidence is complete.

Guardrails enforced in code

  • Tools outside the allowlist are removed from every model request, and refused if called anyway.
  • Paths must be absolute, without .., and under /skills/ or /workspace/. Skills are read-only.
  • There is no host filesystem, shell, web search or account tool. StateBackend keeps files in agent state.
  • Every returned passage is compared with the copy loaded at start-up. If the collection changed mid-turn, research stops.
  • Retrieved text is labelled untrusted evidence in the tool descriptions and the prompt.
  • Both the sanitized prompt and the effective runtime prompt are hashed into the retrieval details, so reports compare like with like.

Run it

# needs the agentic extra; Base RAG preparation is enough
uv sync --all-extras
./rag check --architecture agentic_rag

# ask, with research events streamed as progress
./rag ask --process --architecture agentic_rag "Πότε λήγουν οι Καρδιές;"   # every model and tool call

# tighter budgets to show refusal on exhaustion
./rag chat --architecture agentic_rag --option max_searches=3
./rag ask --architecture agentic_rag --option max_delegations=0 "…"

# see the rendered research prompt, no model call
./rag prompt research --architecture agentic_rag --option max_searches=3

Demo questions

Πότε λήγουν οι Καρδιές; · When do Hearts expire?

A narrow question. Expect: read the hearts skill, one or two searches, maybe one read_clause, then a small selection. Compare the passage count with Base RAG's fixed six.

How do I join Magenta Moments, and can I transfer my Hearts to someone else?

Two topics, two skills. This is the question most likely to use write_todos and a delegation. Watch the event log for delegate.

Can I reuse a coupon code after it was marked as redeemed?

Exercises the coupons skill and its emphasis on negative wording and exceptions.

Same question with --option max_searches=1

Shows budgets in action. A second search raises “PDF search budget exhausted” and the turn is rejected rather than answered on thin evidence.

Pitfalls before class

  • Budget overruns reject the whole turn.Good to teach, awkward when unplanned. Keep defaults for the main demo and show exhaustion on purpose.
  • It is slow and paid.Up to 14 research calls plus the answer, within a 150 s deadline. Run the demo question once before class so you know the timing.
  • Deep Agents names its helper “general-purpose”.The code overrides the default helper with a constrained one of the same name, so no unrestricted worker exists. Students may ask why the name is generic.
  • --process output is long here.Every coordinator and helper model call and tool call is listed. When projecting, show the browser and keep the ./rag ui terminal on a second screen.
