architecture · classic_rag

Base RAG

Embed the question, fetch the six closest passages from Chroma, and have Claude answer only from them, citing passage numbers the application can verify. Every other architecture in the course is this pipeline with a different retrieve step.

Data flow prepare once · ask often

Step by step one turn

  1. Prepare the corpus (once)

    The PDF is split on its clause numbering into chunks of at most 512 Nomic tokens with no overlap. Each chunk keeps its source file, PDF SHA-256, physical page range, clause label and chunk index as metadata, then is embedded and added to Chroma in batches of four.

    rag_core/corpus.py · rag_core/store.py prepare()

  2. Rewrite follow-ups

    On the first message the question is used as is. On a follow-up, Claude sees the last six messages and returns a Rewrite: either a standalone search_query or a clarification question, never both. An ambiguous pronoun produces a clarification instead of a guess.

    rag_core/graph.py prepare_query · templates/rewrite.j2

  3. Retrieve

    One Chroma query with the search query, n_results = top_k, filtered to the current corpus_id. Each hit carries its cosine distance. No model call happens here.

    rag_core/store.py retrieve() · classic_rag/retriever.py

  4. Generate

    Claude receives a JSON payload with the question, the search query, recent history and the numbered evidence. It returns an Answer with text, cited source numbers and a status. The prompt is a Jinja template; runtime data never enters it.

    rag_core/graph.py generate_answer · templates/answer.j2

  5. Validate and format

    The application rejects unknown or duplicate citation numbers, strips inline [n] markers, and appends footers built from metadata, for example [1] Magenta_Moments_Terms_Conditions_gr.pdf · PDF p. 3 · §3.3.

    rag_core/answers.py format_answer()

Answer contract three statuses

answered

Must cite at least one source number from the evidence map. The footer lists only cited passages.

insufficient_evidence

The model's text is replaced by a fixed refusal, in Greek or English depending on which script dominates the question.

clarification_needed

Asks one short question and may cite nothing. Comes from the rewrite step or the generator.

What validation proves

A passing check means every citation points at a passage that was actually retrieved. It does not prove the passage supports the claim. That is what Ragas faithfulness in evals/ measures.

Index identity why “prepare a new collection”

Every chunk and the collection itself store three fingerprints. Opening a collection whose fingerprints differ from the current code fails fast instead of silently mixing vectors.

FingerprintHash ofChanges when
corpus_idPDF names and SHA-256 hashesA PDF is added, removed or edited
embedding_contract_idModel, revision, dims, pooling, prefixes, 512 max tokensEncoder or prefixes change
chunk_config_idclauses-v1, 512 tokens, overlap 0Chunking rules change

Prompt changes do not touch the index. They change prompt_id in eval reports instead.

Run it

# once: start Chroma and embed the PDF
docker compose -f compose.chroma.yaml up -d --wait
./rag prepare
./rag check

# retrieval only: no Anthropic call, shows the 6 passages
./rag search "Πότε λήγουν οι Καρδιές;"

# full turn; --process shows each node and model call as it runs
./rag ask --process "Πότε λήγουν οι Καρδιές;"
./rag ask "Can I exchange hearts for cash?" --top-k 3

# interactive and UI (http://127.0.0.1:8504)
./rag chat
./rag ui

Demo questions

Πότε λήγουν οι Καρδιές; · When do Hearts expire?

Direct lookup. The expiry clause states a calendar rule: Hearts last one year and expire monthly on the 1st day of the 13th month after acquisition. Point out that the answer keeps the PDF's rule verbatim instead of saying “about a year”.

“And can I transfer them?” as a follow-up

Shows the rewrite step. Run it in ./rag chat after the first question and the search query becomes a standalone question about transferring Hearts.

“Can I use it for that?” as the first message

No referent, so the turn should end with clarification_needed and no sources.

What is my current Hearts balance?

Personal account data is not in the corpus. Expect insufficient_evidence and the fixed refusal, even though retrieval still returned six passages. Nonempty retrieval does not prove relevance.

Pitfalls before class

  • Bracketed numbers are read as citations.An answer containing “[2024]” is treated as a reference to source 2024 and the whole turn is rejected. Mostly affects dates or years in brackets.
  • The first turn in a process is slow.Retrieval includes loading the Nomic encoder, about 9 s on a laptop CPU. Run one warm-up question before the demo; --process shows where the time goes.
  • Rewrite must choose exactly one field.If the model returns both or neither of search_query and clarification, the turn fails with an error instead of guessing.
  • History is six messages.Roughly three exchanges. A subject introduced earlier than that can be lost, which then shows up as a clarification.
